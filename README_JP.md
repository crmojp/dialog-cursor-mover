# DialogCursorMover

ダイアログが表示されたとき、指定した遅延の後に **OK ボタン**へマウスカーソルを移動させる Windows 11 用の常駐ユーティリティです。移動時に音を鳴らすこともできます。

[English README](README.md)

**クリックは一切しません。** カーソルを動かすだけなので、誤検出しても勝手に操作が確定することはありません。

---

## 特徴

- `SetWinEventHook` によるダイアログ検出。ポーリングを行わず、待機時の CPU 使用率は 0%
- 5 通りの検出経路により、従来型の Win32 ダイアログ、WPF、WinUI/XAML、TaskDialog のコマンドリンクに対応
- カーソルが動き出すまでの**遅延時間**を設定可能
- 任意の **.wav** を再生。オフにもできます
- 瞬間移動ではなく**滑らかに移動**する演出と、到達地点で**同心円が中心へ縮む**表示
- タスクトレイに常駐し、設定はコンテキストメニューから操作
- 日本語・英語の UI。言語ファイルの追加で拡張可能
- ログオン時に**管理者権限で自動起動**する設定の登録・削除

## 動作環境

- Windows 11（Windows 10 1703 以降でも動作するはずです）
- ビルドには MSVC ツールチェーンの Rust が必要です

依存クレートは `windows-sys` のみです。Win32 を直接呼び出しており、GUI フレームワークは使っていません。

## ビルド

```powershell
cargo build --release
```

ビルド後、実行時に必要なファイルを exe と同じ場所へコピーします。

```powershell
xcopy /E /I lang           target\release\lang
xcopy /E /I assets\theme   target\release\theme
```

### ファイル構成

```
dialog-cursor-mover.exe
lang\
  en.ini
  ja.ini
theme\
  cat\                      サンプルテーマ（任意）
config.ini                  自動生成
log.txt                     自動生成
```

アイコンはビルド時に exe へ埋め込まれるため、`icon.ico` を配布する必要はありません。

実行時のファイルはいずれも必須ではありません。音やカーソルが無ければその機能だけが無効になり、言語ファイルが無ければ組み込みの英語にフォールバックします。

設定とログは exe と同じディレクトリに書き込みます。`Program Files` 配下など書き込めない場所にある場合は `%APPDATA%\DialogCursorMover\` を使います。実際の保存先はトレイメニューの「バージョン情報」で確認できます。

## 使い方

タスクトレイのアイコンを右クリックするとメニューが開きます。

| 項目 | 内容 |
| --- | --- |
| 有効 | ダイアログ監視のオン／オフ |
| ファイル/フォルダー選択ダイアログを無視 | 「開く」「保存」「フォルダーの選択」を対象外にする |
| 遅延時間 | カーソルが動き出すまでの時間（プリセット） |
| 音を鳴らす | オン／オフ、任意の `.wav` の選択 |
| 移動をアニメーションで見せる | 瞬間移動ではなく滑らかに移動 |
| 速度 | 速い／普通／遅い |
| 到達地点に同心円を表示する | 着地点で同心円が中心へ縮む |
| 移動中カーソル画像を差し替える | 別途 `.ani` を用意した場合のみ |
| ログオン時に管理者権限で自動起動 | タスクスケジューラへの登録・削除 |
| 診断 | テストダイアログ、ログレベル、ログを開く、言語 |
| 設定ファイルを開く／設定を再読み込み | `config.ini` の編集と反映 |

動作確認には**「診断」→「テストダイアログを表示」**が便利です。

## 言語

UI の文字列と `config.ini` のコメントは `lang\<コード>.ini` から読み込みます。既定は英語です。

トレイメニューから言語を切り替えると `config.ini` がその言語のコメントで書き直されますが、**設定値はすべて引き継がれます**。キー名と値の書式は言語に依存しないため、翻訳されるのはコメントだけです。

### 言語を追加する

`lang\en.ini` をコピーして値を訳し、`lang\<コード>.ini` として保存してください。メニューの言語一覧に自動的に現れ、表示名には `lang.name` の値が使われます。

```ini
; ';' で始まる行はコメント
lang.name = 日本語                       ; 言語メニューに表示される名前
menu.enabled = 有効                      ; 単純な文字列
menu.delay.current = 現在: {0} ms        ; {0} は実行時に置換
cfg.enabled = 監視を有効にするか\nどうか。  ; \n は改行になります
```

`cfg.<設定名>` が `config.ini` の各項目に付くコメントになります。キーが欠けていたり値が空の場合は組み込みの英語にフォールバックするので、部分的な翻訳でも問題ありません。

## テーマ

アイコン、移動中のカーソル、音は、exe と同じ階層の `theme\` にフォルダを置く
ことで差し替えられます。

```
dialog-cursor-mover.exe
theme\
  cat\
    icon.ico
    cursor_right.ani  cursor_right_fast.ani  cursor_right_slow.ani
    cursor_left.ani   cursor_left_fast.ani   cursor_left_slow.ani
    sound.wav
```

トレイメニューの**「テーマ」**から選択します。フォルダ名がそのままテーマ名です。
ファイルはいずれも任意で、無いものは内蔵アイコンと Windows のカーソル・音に
フォールバックします。音だけを差し替えるテーマも作れます。

テーマを選ぶと**「移動中カーソル画像を差し替える」**が自動的に有効になり、
既定に戻すと無効になります。テーマを選んだならそのカーソルを見たいはずで、
既定に戻したなら Windows のカーソルを使いたいはず、という想定です。
これが働くのは切り替えた瞬間だけで、その後に手動で切り替えた設定はそのまま残ります。

カーソルの 3 種類は**「速度」**の設定に対応します。必須なのは
`cursor_<左右>.ani` だけで、`_fast` と `_slow` は存在すれば使われ、
無ければ無印を流用します。3 つ揃えるとコマ送りの速さが移動速度と揃うため、
速い・遅いの設定でも動きが自然になります。

サンプルとして `cat` テーマを同梱しています。作り直したり、自分のテーマの
出発点にする場合は次のコマンドを使ってください。

```powershell
py -m pip install pillow numpy
py assets\make_theme_cat.py
```

このスクリプトは、アイコンと 6 フレームのカーソルを Pillow で描き、`.ani` は
Pillow が書き出せないためバイナリを直接組み立て、音を NumPy で合成しています。

### テーマを作る

#### ディレクトリとファイル名

exe と同じ階層の `theme\` の下に、テーマ名のフォルダを 1 つ作ります。
**フォルダ名がそのままテーマ名**になり、メニューに表示されます。

```
dialog-cursor-mover.exe
theme\
  my-theme\              ← 半角英数字・ハイフン・アンダースコアのみ、64 文字以内
    icon.ico
    cursor_right.ani
    cursor_right_fast.ani
    cursor_right_slow.ani
    cursor_left.ani
    cursor_left_fast.ani
    cursor_left_slow.ani
    sound.wav
```

ファイル名は**下表のとおり固定**です。大文字小文字は環境に依存するため、
すべて小文字で揃えてください。サブフォルダには置けません。

| ファイル名 | 用途 | 無い場合 |
| --- | --- | --- |
| `icon.ico` | トレイアイコン | 内蔵アイコン |
| `cursor_right.ani` | 右向き・普通 | カーソルを差し替えない |
| `cursor_right_fast.ani` | 右向き・速い | `cursor_right.ani` |
| `cursor_right_slow.ani` | 右向き・遅い | `cursor_right.ani` |
| `cursor_left.ani` | 左向き・普通 | カーソルを差し替えない |
| `cursor_left_fast.ani` | 左向き・速い | `cursor_left.ani` |
| `cursor_left_slow.ani` | 左向き・遅い | `cursor_left.ani` |
| `sound.wav` | 移動時の音 | Windows のシステム音 |

**すべて任意です。** 音だけのテーマ、アイコンだけのテーマも作れます。
1 ファイルあたり 8 MB を超えるものは読み込まれません。

#### アイコン (`icon.ico`)

Windows の ICO 形式です。トレイアイコンには
`GetSystemMetrics(SM_CXSMICON)` のサイズが要求されるため、
**16×16 と 32×32 は必ず含めてください**。高 DPI 環境では 24、40、48 も
使われます。

同梱の `cat` テーマは 16 / 20 / 24 / 32 / 40 / 48 / 64 / 128 / 256 の
9 サイズを収めています。

**透過は 32bpp のアルファチャンネル**を使ってください。トレイの背景は
ライトテーマとダークテーマで大きく変わるため、特定の色を透明色として
指定する古い方式では縁が残ります。

トレイは 16×16 で表示されます。細部は潰れるので、輪郭が読める
シルエットを優先してください。大きいサイズで描いてから縮小すると、
16×16 で判別できないことがよくあります。

#### カーソル (`cursor_*.ani`)

Windows のアニメーションカーソル形式です。

| 項目 | 値 |
| --- | --- |
| サイズ | 32×32（標準の DPI の場合） |
| 色深度 | 32bpp（アルファチャンネル付き） |
| フレーム数 | 制限なし（同梱テーマは 6） |
| ホットスポット | 進行方向の先端に置く |

**左右 2 方向が必要です。** 移動の向きに応じて `right` と `left` が
切り替わります。左向きは右向きを左右反転させたもので構いません。

**ホットスポット**はカーソルの論理座標で、ここがボタンの中心に一致します。
進行方向の先端（右向きなら右端、左向きなら左端）に置くと、本体が後ろから
ついてくるように見えます。中央に置くと着地の瞬間に本体がボタンからはみ出ます。

**速度別の 3 種類**は、コマ送りの速さだけが違うファイルです。
`.ani` のコマ送り速度はファイル内に記録され実行時に変更できないため、
速度ごとに別ファイルを用意する必要があります。同梱テーマの値は次のとおりです。

| 速度 | 移動時間 | コマ送り |
| --- | --- | --- |
| 速い | 160 ms | 約 50 ms/コマ |
| 普通 | 320 ms | 約 83 ms/コマ |
| 遅い | 640 ms | 約 133 ms/コマ |

無印だけを用意した場合、速度を変えても常にそのファイルが使われます。
動作はしますが、移動の速さと絵の動きが合わなくなります。

`.ani` は一般的な画像編集ソフトでは書き出せません。専用のカーソル
エディタを使うか、同梱の `assets\make_theme_cat.py` のようにバイナリを
組み立ててください。

#### 音 (`sound.wav`)

RIFF WAVE 形式です。次の制約があります。

- 拡張子は `.wav`（他の形式を `.wav` に改名しても再生されません）
- 16 MB 以下、かつテーマファイルとしての上限 8 MB 以下
- ネットワーク上のパスは不可（テーマは exe と同じ階層にあるため通常は問題になりません）

**長さは 500 ms 以内**を目安にしてください。移動そのものが 160〜640 ms で
終わるため、それより長い音は次の操作に重なります。

同梱テーマは 44.1 kHz / 16 bit / モノラル、振幅は最大の 50% に抑えています。
通知音は繰り返し鳴るものなので、音量は控えめにしておくと使い続けやすくなります。
先頭と末尾の振幅を 0 にしておくと、再生開始・終了時のプツッという音を防げます。

#### 反映のしかた

テーマはメニューを開いた時点で `theme\` を読み直します。フォルダを追加した
場合はメニューを開き直すだけで一覧に現れます。ファイルを差し替えた場合は、
アイコンとカーソルがキャッシュされているため、テーマを選び直すか
アプリを再起動してください。

#### 配布するとき

テーマは第三者が持ち込むものとして扱われるため、シンボリックリンクや
テーマフォルダ外を指すファイルは読み込まれません。フォルダごと ZIP に
まとめて配布するのが確実です。

## OK ボタンの探し方

次の 5 経路を、この優先順で試します。

### 1. HWND・ラベル一致

子ウィンドウを走査し、**ラベルの一致を必須条件**とします。既定で認識するのは `OK` / `はい` / `Yes` / `了解` / `続行` / `Continue` と、`extra_button_labels` に指定したものです。ニーモニックは除去されるので、`保存(&S)` は `保存` として比較されます。

コントロール ID や `BS_DEFPUSHBUTTON` は、候補が複数あるときの順位付けにのみ使います。単独の根拠にはしません。`IDOK` はスコアに 100 を加えるので、標準の `MessageBox` の OK ボタンが同じダイアログ内の他の候補に負けることはありません。

**ラベルを見ずに `IDOK` を採用する近道は、意図的に設けていません。** Win32 アプリはメインウィンドウをダイアログとして作ることがあり、その場合クラスは `#32770` になり、主要な操作ボタンが ID=1 を持ちます。たとえばファイル転送ツールの「実行」ボタン——押せばコピーや削除が始まるもの——がこれに該当します。ラベル照合を必須にすることで、規則が一文で説明できる状態を保っています。「認識できるラベルのボタンか、下の配置判定を通った既定ボタンにだけカーソルを移動する」。

ボタンのクラス名は部分一致で判定するため、`Button` のほか `TNewButton`（Inno Setup）や `TButton`（Delphi）も受け入れます。`BS_OWNERDRAW` も対象です。自前描画は見た目が違うだけで、押しボタンであることに変わりはないためです。

### 2. HWND・既定ボタン

ラベルが一致せず `follow_dialog_default_button` が有効な場合、`BS_DEFPUSHBUTTON` を次のいずれかの条件で採用します。

- 同じ並びに「キャンセル」相当のボタンがある（ウィザードの「次へ / キャンセル」など）
- ダイアログ下端から 25% の範囲にある（情報ダイアログの「閉じる」など）

ボタン自身のラベルが「キャンセル」相当の場合は選びません。インストーラの実行中は「次へ」が無効化されて「キャンセル」が既定ボタンになることがあり、そこへ移動するのは意図と正反対になるためです。

この判定は**ブラウザの中では行いません**（`follow_default_in_browser`、既定 `false`）。Web ページは任意の UI を作れるため、「ブロック / キャンセル」のような並びを本物のダイアログのボタン行と構造的に区別できません。

ボタンの並びは横（OK / キャンセル）と縦（TaskDialog のコマンドリンク）の両方を認識します。

### 3. UI Automation

XAML、WinUI、WPF のダイアログは実 HWND のボタンを持ちません。この場合は `ElementFromHandle` から `FindAll(TreeScope_Descendants)` を実行し、次の条件を満たす要素を探します。

- `ControlType` が `Button` (50000) または `Hyperlink` (50005)
- 有効かつ画面内にある
- 名前が上記のラベル一覧に一致する

`CreatePropertyCondition` で UIA 側に絞り込ませています。これがないとブラウザのウィンドウでは数千要素が返り、そのすべてにクロスプロセスのプロパティ取得が走ります。

### 4・5. フォーカス

ダイアログの中には、ホストウィンドウの**内側に描画**され、新しい HWND を作らないものがあります。XAML ベースの新しいエディタが出す「変更内容を保存しますか?」の類がこれに当たります。ウィンドウを見ていても検出できませんが、ダイアログが開くとフォーカスが既定ボタンへ移るため、`EVENT_OBJECT_FOCUS` を契機に `GetFocusedElement` を確認します。ツリー走査をしないので UIA 呼び出し 1 回で済みます。

ラベル一致と既定ボタンの規則は同じで、ログには `[FOCUS]` と `[FOCUS(既定)]` として現れます。

## 検出のきっかけ

4 種類の WinEvent をフックしています。

| イベント | 目的 |
| --- | --- |
| `EVENT_SYSTEM_DIALOGSTART` | 標準的なダイアログ |
| `EVENT_OBJECT_SHOW` | 上記で拾えないウィンドウ |
| `EVENT_SYSTEM_FOREGROUND` | ウィンドウを使い回すアプリへの保険 |
| `EVENT_OBJECT_NAMECHANGE` | 同じウィンドウのまま中身が差し替わるダイアログ |
| `EVENT_OBJECT_FOCUS` | ウィンドウの内側に描画されるダイアログ |

タイトル監視はエクスプローラの「ファイルの置換またはスキップ」のためにあります。これは新しいウィンドウではなくコピー進捗ウィンドウが中身を書き換えたもので、表示イベントが飛びません。タイトルが「87% 完了」から変わることだけが手がかりになります。

## 除外される対象

判定は下の順に行い、いずれかに該当した時点で処理を終えます。したがって
**除外設定は `extra_button_labels` より常に優先されます**。タイトルや
プロセスで除外されたダイアログは、そもそもボタンを探す段階に進まないため、
ラベルの一覧が参照されることもありません。

| # | 段階 | 関係する設定 |
| --- | --- | --- |
| 1 | そもそもダイアログか | `standard_dialog_only`, `uia_dialog_like_only` |
| 2 | 前面にあるか | `require_foreground` |
| 3 | 自分自身のダイアログか | `ignore_own_process` |
| 4 | 既に反応済みか | `move_once_per_dialog` |
| 5 | *(遅延の後)* タイトルによる除外 | `exclude_titles` |
| 6 | プロセスによる除外 | `exclude_processes` |
| 7 | ファイル選択ダイアログか | `skip_file_dialogs` |
| 8 | 処理中ダイアログか | `skip_progress_dialogs` |
| 9 | **OK ボタンを探す** | `extra_button_labels`, `follow_dialog_default_button` |
| 10 | 既にカーソルがボタン上か | `skip_if_cursor_inside` |

5〜8 が遅延の**後**にあるのは、ダイアログが現れた瞬間には子コントロールが
揃っていないことがあるためです。

`extra_button_labels` で除外を上書きする手段はありません。特定のダイアログ
だけ例外にしたい場合は、除外の指定を狭めてください。タイトルの部分一致を
より具体的にする、プロセス除外をタイトル除外に置き換える、といった方法です。

**候補ウィンドウ**は「ダイアログらしい形」であることが条件です（`uia_dialog_like_only`）。タイトルバーまたは表題を持ち、モニタの 80% を超えず、「オーナーを持つ」「リサイズできない」「モニタの半分未満に収まる」のいずれかを満たす必要があります。一時的なシェルのウィンドウ（`SysDragImage`、`tooltips_class32`、`SysShadow`、トレイのオーバーフロー）はクラス名で除外します。

タイトルの条件に `WS_CAPTION` だけでなく表題文字列も認めているのは、タイトルバーを自前で描くアプリがあるためです。

画面サイズは `MonitorFromWindow` からそのウィンドウが載っているモニタのものを取ります。プライマリ固定ではないので、マルチモニタ環境でも正しく判定できます。

**ファイル選択ダイアログ**はシェルのビュー（`SHELLDLL_DefView`）を内包することで判別します。決定ボタンが `IDOK` を持つため、クラスやラベルでは通常のダイアログと区別できないからです。

ただしビューの有無だけでは足りません。ファイルのプロパティも「以前のバージョン」タブでビューを作るため、そのタブを開くと選択ダイアログに見えてしまいます。そこで条件を 2 つ加えています。ビューが**表示中**であること、そしてタブコントロール（`SysTabControl32`）を持たないことです。選択ダイアログにタブはなく、プロパティシートには必ずあります。

**処理中ダイアログ**は表示中のプログレスバー（`msctls_progress32`、または UIA の ControlType 50012）で判別します。表示中のものだけを見るため、プログレスバーが隠れているエクスプローラの置換確認には反応します。

**同じダイアログへの再反応**は抑止されます。設定ダイアログのタブを切り替えると各ページの表示イベントが飛び、ウィンドウを再アクティブにしても同様です。これがないと、そのたびにカーソルが OK へ戻ってしまいます。

記録の鍵はウィンドウのみで、ボタンの位置は含めません。位置を含めると、ダイアログを画面上でドラッグしただけで別物と判定され、アクティブにするたびに反応してしまうためです。記録はウィンドウが閉じられた時点で消えるので、開き直せば通常どおり反応します。

ウィンドウの内側に描画されるダイアログだけは別の方法で判定します。こうしたダイアログはウィンドウを持たず、記録できるのはホストとなるアプリのウィンドウだけです。それを「閉じるまで」抑止するとアプリを終了するまで二度と反応しなくなるため、代わりに**フォーカスの状態**で判定します。フォーカスがボタンから外れた時点でダイアログが閉じたとみなし、記録を解除します。

## 走る演出

`move_animation` が有効なとき、カーソルは smoothstep で加速・減速しながら `move_duration_ms` かけて移動し、進行方向と垂直に小さく揺れます。揺れは終端で 0 に収束するため、着地点は必ずボタンの中心です。

速度は「速い」（160 ms）、「普通」（320 ms）、「遅い」（640 ms）の 3 段階です。それぞれにコマ送り速度の異なるカーソルを用意しています。移動時間だけを変えると脚の回転が合わなくなるためです。

走行中にユーザーがマウスを動かすと移動を中断します。昇格したウィンドウが前面のときはカーソルの反映が 1 ティックぶん遅れることがあるため、直前のティックで指示した移動量を許容範囲に加えて判定しています。

### カーソル差し替えの注意

`SetSystemCursor` はデスクトップ全体のカーソルを変更するため、差し替えたままプロセスが落ちると元に戻りません。三重の保険をかけています。差し替え中はマーカーファイルを置き、起動時にマーカーが残っていれば無条件で復元し、`WM_DESTROY` と `WM_ENDSESSION` でも復元します。

万一戻らなくなった場合は、本アプリを起動し直すか、**設定 → Bluetooth とデバイス → マウス → マウスの追加設定 → ポインター → 既定の設定**で戻せます。

## 管理者権限のアプリへの対応

本アプリを通常起動している限り、**管理者権限のウィンドウが前面にある間はカーソル移動が完全に拒否されます**。これは UIPI による制限で、権限を要求して回避できるものではありません。検出もボタンの特定も成功しますが、カーソルは動きません。この場合、音は意図的に鳴らしません。音はカーソルが実際に動いたことを確かめてから再生するため、**何も起きない**ことが妨げられている合図になります。

```
中断: カーソル移動が拒否されました。前面のウィンドウが管理者権限で
実行されている可能性があります
```

| 機能 | 非昇格での状態 |
| --- | --- |
| WinEvent フック | 届くことが多い |
| `EnumChildWindows` | 動作する |
| UI Automation | 遮断されがち |
| `exclude_processes` | **効かない**（`OpenProcess` が失敗するため） |
| `SetCursorPos` | **拒否される** |

`exclude_processes` が効かない場合は `exclude_titles` で代替してください。

**回避するには本アプリを管理者として実行する以外に方法はありません。** ただし常時昇格した常駐プロセスは攻撃対象になり得るため、対象アプリを使う頻度と天秤にかけて判断してください。

UAC の同意画面はセキュアデスクトップにあり、いずれにせよ届きません。これは設計上そうあるべきものです。

## 自動起動

通常起動でよければ `shell:startup` にショートカットを置いてください。

管理者権限で起動する場合は、トレイメニューの**「ログオン時に管理者権限で自動起動」**を使います。`DialogCursorMover` という名前のタスクがタスクスケジューラに登録されます（ログオン時トリガー、最上位の特権、バッテリー駆動でも実行）。登録時に UAC のプロンプトが 1 回出ます。チェックを外すと削除されます。

**exe を移動・改名した場合は登録し直してください。** タスクにはパスが記録されています。

昇格したプロセスは、非昇格の Explorer が送る `TaskbarCreated` を拒否するため、そのままではログオン時にトレイアイコンが出ません。`ChangeWindowMessageFilterEx` でこのメッセージだけ受信を許可し、加えてタスクバーがまだ無い場合に備えて 3 秒間隔で最大 20 回まで登録を再試行します。

**Windows サービスとしては動作しません。** サービスはセッション 0 で動作しユーザーのデスクトップから隔離されるため、フック・カーソル操作・トレイアイコンのいずれも機能しません。

## 診断

**「診断」→「ログ: 詳細」**を有効にして問題を再現し、ログを開いてください。除外された場合は必ず理由が記録されます。

| ログの内容 | 対処 |
| --- | --- |
| `対象外 ... class="..."` | 標準ダイアログではない。`standard_dialog_only = false` を試す |
| `中止: ダイアログが前面ではありません` | `require_foreground = false` にする |
| `中止: OK ボタンが見つかりません` | 同じ行に見つかったボタン名が並ぶので `extra_button_labels` に追加する |
| `中断: カーソル移動が拒否されました` | 本アプリを管理者として実行する |
| 何も記録されない | HWND も UIA 情報も持たないダイアログの可能性 |

詳細ログは 1 時間あたり数千行に達するため、常用時は**「通常」**か**「オフ」**に戻してください。

ログは 1 MB を上限とし、達すると古いほうの約半分を捨てて残りを保持します。直近の記録は必ず残ります。分割位置はバイト数ちょうどではなく**行の切れ目**に合わせます。ログにはウィンドウタイトルが入り日本語を含むため、文字の途中で切ると文字化けするためです。

## リソース消費

待機時の CPU 使用率は 0% です。メッセージループは `GetMessageW` でブロックし、ポーリングは行いません。

ホットパスではヒープ確保を行いません。`EVENT_OBJECT_NAMECHANGE` はデスクトップ全体で頻繁に飛ぶため、`Config` を clone せずスカラー値だけの `Copy` なスナップショットを使い、クラス名の比較もスタック上で行います。

ログはファイルハンドルを開いたまま保持し、サイズも自前で数えて `metadata()` の呼び出しを避けています。

唯一重い処理は UIA 走査です。そのため ControlType による絞り込み、同一ウィンドウあたり 600ms のスロットリング、`uia_max_elements` による上限を設けています。プロセスメモリの大半は `UIAutomationCore.dll` で、`uia_enabled = false` にすれば読み込み自体を回避できます。

起動時にプロセスをモニタ単位の DPI 対応にしています。これを省くと `GetWindowRect` と `SetCursorPos` が仮想化された座標を扱う一方、UIA は物理座標を返すため、拡大表示のディスプレイで移動先がずれます。

## 既知の制限

- **UAC の同意ダイアログ**はセキュアデスクトップ上にあり、到達できません。
- **UI をすべて自前で描画するアプリ**は HWND の子ウィンドウも UIA 要素も公開しません。一部のクロスプラットフォーム系ツールキットや独自のウィジェットライブラリが該当し、ボタンの位置を知る手段がありません。
- **Web ページ内のダイアログ**はページの実装に依存します。フォーカスがボタンに当たらない場合、検出のきっかけがありません。
- `delay_ms` が 200 ms を大きく下回ると、ボタンの配置が確定する前に動くことがあります。

## 開発

```powershell
cargo test          # 単体テスト
cargo clippy --all-targets -- -D warnings
cargo fmt --all
```

テストは、実行中の Win32 の状態に依存しない部分を対象にしています。ラベルの正規化と判定、ボタンの並びの幾何判定、言語コードの検証と値の正規化、そして **全設定項目の往復**（`to_ini` / `parse_ini`）です。

最後のものが最も重要です。設定は 34 項目あり、追加時には読み込みと書き出しの両方に手を入れる必要があります。片方だけの実装ならテストが落ちるので、「設定が黙って失われる」という形で数か月後に気づく事態を防げます。

CI は `windows-latest` で実行します。Win32 を直接呼ぶため他の環境ではビルドできないためです。あわせて、すべての言語ファイルが `en.ini` と同一のキー集合を持つことも検証するので、訳し忘れをリリース前に検出できます。

`v*` のタグを push すると、exe・音・カーソル・言語ファイル・文書を含む zip を作成し、不足がないか確認したうえで GitHub Release に添付します。

## セキュリティ上の注意

### 信頼境界は exe のあるディレクトリです

`config.ini`、`log.txt`、`lang\`、音、カーソルはいずれも exe と同じ場所に置かれ、そこから読み込まれます。つまり**そのディレクトリに書き込める者は、このアプリの挙動を変更できます**。管理者権限で自動起動する設定にしている場合、その挙動は管理者権限で実行されます。

管理者だけが書き込める場所に配置するか、自分のプロファイル配下に置いて、他の実行ファイルと同じように扱ってください。他のユーザーや非特権のサービスが書き込めるディレクトリには置かないでください。

exe のディレクトリが書き込めない場合、設定は自動的に `%APPDATA%\DialogCursorMover\` へ退避します。共用のマシンではこちらのほうが安全な構成です。

### 信頼できない入力の扱い

`config.ini` の解析は防御的に行っています。数値は `parse` とフォールバックを経てから範囲に丸められるため、不正な値や範囲外の値を書いても既定値に戻るだけです。文字列は所有権を持つ `String` として扱い、固定長バッファへコピーすることはありません。

`language` はパスの一部になる前に検証します。この検査がないと、`Path::join` の仕様により絶対パスが基準ディレクトリを置き換えてしまい、`language = C:\...` や UNC パスの指定で `lang\` の外を読めてしまいます。

`wav_path` は任意の場所を指定できる唯一のアセットなので制限を設けています。UNC パスは拒否し（リモートパスは再生のたびに外部接続を発生させます）、拡張子は `.wav` に限定し、16 MB を超えるファイルは受け付けません。アイコンとカーソルは exe と同じディレクトリの固定ファイル名を使うため、参照先を変更できません。

**言語ファイルは他のアセットより少し注意が必要です。** 解析するのが Windows ではなくこのアプリ自身であること、内容がメニューのラベルや `config.ini` のコメントに流れ込むこと、そしてアイコンやカーソルと違い**第三者が作った翻訳を持ち込むことを想定している**ためです。そのため読み込み時に値を正規化します。NUL とその他の制御文字を除去し（NUL があると Win32 が描画する際に文字列がそこで切れます）、値は 2000 文字、ファイルは 512 KB・2000 キーで打ち切ります。改行として残るのは `\n` と書かれたものだけで、これは `config.ini` のコメントに必要なぶんです。

とはいえ、言語ファイルは目に見えるすべての文字列を変更できます。翻訳を導入する前には中身を確認してください。exe と同じ場所に置く他のファイルと同様に扱うべきものです。

ログに記録されるウィンドウタイトルは他プロセス由来で、改行を含む任意の文字列になり得ます。制御文字を置換し、1 行の長さを制限してから書き出すため、タイトル側から新しい行を始めてログを丸ごと捏造することはできません。ただし 1 行の中では書かれたとおりに現れるので、引用符で囲まれた値は「アプリが保証した内容」ではなく、他プロセスが決めた文字列として読んでください。

**ログにはウィンドウタイトルが残ります。共有する前に中身を確認してください。** `log_level = 1` では反応したダイアログのタイトルが、`2` ではイベントを出したすべてのトップレベルウィンドウのタイトルと、その中で見つかったコントロール名が記録されます。通常の使用では、文書名・ブラウザのページタイトル・通知の内容などが含まれます。不具合報告に添付する前に `log.txt` を確認してください。

**テーマは言語ファイルと同じ扱いです。** 共有されることを想定しているため、
テーマのフォルダは exe と同じ信頼レベルとは見なしません。テーマ名はパスの一部に
なる前に検証し、ファイルは 1 つあたり 8 MB までに制限し、シンボリックリンクや
ジャンクションは受け付けず、解決後のパスがテーマのフォルダ内に留まることを
確認します。音は `wav_path` と同じ検査を通ります。

一方で**中身までは検査できません**。`.ico` `.ani` `.wav` を解析するのは
Windows であってこのアプリではありません。ダウンロードしたテーマは、exe と同じ
場所に置く他のファイルと同様に扱ってください。

### このアプリが行わないこと

クリックは一切せず、他のウィンドウへ入力を送ることもありません。

起動する外部プロセスは 3 つで、いずれもカレントディレクトリが先に探索されないよう絶対パスで呼び出します。自動起動登録時の `schtasks.exe`（シェルを経由せず引数配列で渡します）、ログや設定ファイルを開くときの `notepad.exe`、そして自動起動の登録に管理者権限が必要なときに `runas` で起動し直す自分自身です。

ネットワーク通信は行わず、テレメトリも収集しません。書き込むのは `config.ini` と `log.txt` だけです。

UAC の同意画面はセキュアデスクトップ上にあり到達できません。これは意図したもので、UAC が強いる一拍こそがセキュリティ機能であり、「はい」へカーソルを寄せることはその価値を損ないます。
